See it work

Everything happens in the document.

Reading, editing, restyling, and saving all happen in the open file. There is no app to launch, no export step, and no separate diagram tool.

Markdown, unchanged

Edit the source you already know

Press Cmd/Ctrl+Shift+E to open the source tray. Inside is ordinary Markdown with YAML frontmatter - headings, lists, tables, links, code fences, callouts. Type a new section or a whole new diagram and the document re-renders as you go.

  • Canonical Markdown is the stored truth, not a lossy round trip
  • Readable in a diff, so documents review like code
  • Nothing proprietary to learn before you can fix a typo
Built-in diagram editor

Full control over layout and colour

Select a node to open the inspector: label, subtitle, shape, palette, status colour, custom fill and stroke, alignment, and exact size. Drag to reposition, resize with handles, duplicate a node, and route new edges between them.

  • Every change is written back into the diagram YAML
  • Semantic palettes and statuses keep a document visually consistent
  • No Visio, no draw.io, no exported PNG that drifts out of date
Themes and colour schemes

Beautiful in whichever mode you read in

The document menu switches theme between auto, light, and dark, and picks a colour scheme - classic, ice, midnight, or paper. Prose, callouts, and diagrams all re-theme together.

  • Diagrams are live SVG, so they follow the theme instead of fighting it
  • auto follows the reader's system preference
  • A menu change becomes canonical frontmatter when you save
Big diagrams, small screens

Zoom in without losing the thread

Switch to full-width layout to give a complex system more room, then zoom in, zoom out, or fit the diagram to its frame. Because the diagram is vector, detail stays crisp at any magnification and the surrounding prose stays where it was.

  • Centred or full-width layout, switched as you read
  • Sharp on a laptop, a 4K monitor, or in print
  • Panning is visual only - stored coordinates stay untouched
Why it matters

Agent output that survives contact with a team.

Most agent-written documentation dies on delivery: the diagram is an image, the formatting is bespoke, and the only way to change anything is to ask the agent again.

Correct it yourself

Spotted a wrong label or a missing step? Fix it in the source tray or drag the node. You do not need the original agent, its context, or its environment.

Keep it in version control

The document is text: Markdown plus YAML inside one HTML file. Diffs are readable, reviews are meaningful, and history stays honest.

Share it anywhere

Save As keeps the file small against the hosted runtime. Save for Offline embeds a pinned runtime so the document works with no network at all.

Cheap for agents to produce

Agents write plain Markdown and explicit diagram YAML - no image generation, no headless browser, no rendering service. One install keeps them on-contract.

The workflow

Three steps, no pipeline.

No CMS, no build step, no diagram service, no export dance. An agent writes a file, a browser renders it, a person improves it.

Describe the system

02 / RENDER

03 / REFINE

People edit the source, drag and restyle diagrams, and save an updated document without leaving the browser.

For agents

One command and your agent knows the format.

Install the skryb-document skill and any supported local agent gets the schema-aware authoring contract - the HTML shell, the Markdown subset, and every diagram field it is allowed to use.

npx skills add sparkkz-nz/skryb \
  --skill skryb-document \
  --agent '*' \
  --global \
  --yes \
  --full-depth

Omit --global to install it for the current project only. Keep it current with npx skills update --global.

The skill is versioned alongside the runtime, so an agent writes documents that match the runtime rendering them.

  • No image generation, headless browser, or rendering service in the loop
  • Agents write plain Markdown and explicit diagram YAML, and nothing else
  • Invented frontmatter keys, fields, and diagram types are ruled out by contract
  • Pin a release runtime URL when a document has to keep rendering the same way
